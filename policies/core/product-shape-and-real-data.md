# Product Shape and Real Data

- Preserve the backend-selected artifact type, product shape, interaction model, generation depth, output paths, and prohibited defaults.
- Choose the smallest complete solution. Do not substitute a webpage for a document, PDF, image, presentation, workbook, mobile app, API, script, automation, service, or media artifact.
- Existing projects are bounded product changes unless the user explicitly requests broader redesign or architecture work.
- Use real APIs, databases, external integrations, uploaded sources, or user-provided content. Otherwise provide honest empty, loading, error, or configuration states.
- Never invent business records, people, clients, testimonials, metrics, transactions, financials, or integration success.
- Consume supplied inputs or preserve them with explicit unresolved evidence.
- Validate the requested artifact using domain-appropriate evidence, not a decorative preview alone.
