# Decision Continuity identity threat model

| Threat | Control | Residual risk / owner |
| --- | --- | --- |
| Forged, expired, wrong-issuer, wrong-audience, unsigned, or key-confused bearer token | Asymmetric OIDC verification, strict issuer/audience/type/time checks, JWKS key selection and bounded rotation refresh | Identity-provider signing-key compromise or issuer outage remains with the identity platform owner. |
| Tenant spoofing in browser header/query/body/path | Verified principal plus active PostgreSQL membership; conflicting selectors reject; resource reads are tenant scoped and non-enumerating | Application currently connects as DB owner, so RLS rollout needs a non-owner runtime role. Database/platform owner. |
| Client self-promotion to administrator/service | No client role/scopes are read; provisioning has no HTTP route; service ignores human roles | Controlled database-admin process must be reviewed and audited. Security/DB owner. |
| Service self-approval or autonomous-agent policy administration | Service approval scope is schema-rejected; service approvals denied in code; QAgent/BrainX policy deny | Identifier-based QAgent/BrainX classifier is a defense-in-depth guard; maintain principal naming governance. Platform owner. |
| Originator evaluates/approves its own branch | Server-side originator/reviewer/approver checks plus state-machine checks | Historical branches missing provenance can require manual remediation before strict retrospective enforcement. Product governance owner. |
| Revoked submitter's queued work executes | Membership and permission rechecked at worker effect time; authorization failures are permanent DLQ | A request/effect already past its check can finish. Bound is one in-flight operation plus normal lease timing. Operations owner. |
| Bearer theft through browser persistence or CSRF | Memory-only bearer; no ambient cookie credentials; production origin allowlist | XSS can still use in-memory tokens. Maintain CSP, sanitization, dependency review, short token TTL, and IdP MFA. Frontend/security owner. |
| Audit log credential disclosure | Metadata sanitizer and database-only audit fields omit tokens, headers, credentials, and claims | Database administrators can still inspect other application tables; log retention/access policy required. Security operations owner. |
| JWKS/issuer outage or stale key | Fresh cache and bounded stale grace; failures fail closed after grace | Availability trade-off during IdP outage. Identity platform owner sets SLA and rotation runbook. |
| SAML parser/metadata weakness in API | SAML stays behind an OIDC broker boundary; API validates only broker-issued OIDC | Broker selection, metadata signing, and SAML lifecycle are external identity controls. Identity platform owner. |
| QAgent prompt injection raises tool, budget, recursion, or authority limits | Strict structured proposal schema rejects undeclared fields; hard server limits and tenant feature flags are resolved outside model output | Deployment configuration can still be set too generously by an authorized operator; migration/application ceilings cap values. Platform owner. |
| QAgent collector exfiltrates or writes through an unrestricted tool | Collector must be server-registered, explicitly read-only, and source/tool allowlisted; no browser mutation endpoint exists | Collector implementation must be independently reviewed before production registration. Security owner. |
| Stale, unauthorized, or conflicting QAgent evidence clears a constraint | Deterministic authorization/freshness/digest/size checks; rejected evidence is retained only as untrusted metadata; independent evaluator schema cannot emit `cleared` | Upstream source authorization and clock integrity remain source-owner concerns. Evidence owner. |
| Duplicate delivery or restart repeats a paid/tool action | Tenant-scoped idempotency effect claims persist before collection; completed effects replay outcome; pending effects stop for recovery rather than blindly re-execute | A collector must provide an idempotency-aware recovery lookup before automatic resume is enabled. Operations owner. |
| QAgent self-evaluates, approves, promotes, or administers policy | QAgent identity is rejected as independent evaluator; no such service methods; membership constraint and existing QAgent/BrainX policy denial block lifecycle authority | Identifier-based identity classifier remains defense in depth; use controlled principal provisioning. Platform owner. |
| BrainX registration uses a moving, executable, or unverified model artifact | Immutable revision/checksum, Hugging Face safe-format allowlist, `trustRemoteCode: false`, immutable registration versions, and fixture-only adapter boundary | Operator-supplied provenance/licence/evaluation evidence must be independently reviewed before activation. Model-governance owner. |
| BrainX routes sensitive data to an unapproved provider/region/egress | Server-held eligibility checks use tenant/sensitivity/licence/region/egress/health/hardware/budget policy; route exclusions are stored; no eligible model fails closed | Registration and policy inputs remain governance-owned configuration. Privacy/model-governance owner. |
| Model output performs tools, shell/SQL, policy, constraint, or promotion actions | Strict output schema, deterministic control-like content validator, digest-only retention, no output consumer wired to privileged paths, separate service identity | Natural-language output remains untrusted validator input; downstream integrations require their own reviewed boundary. Platform owner. |
| Duplicate, timeout, failing, or runaway model execution bills/repeats work | Persisted idempotency effect claim, bounded timeout/fallback/concurrency/cost limits, circuit state, cancellation, and scoped kill controls | An in-flight isolated adapter call can consume its bounded allocation before cancellation; provider recovery semantics need owner review before production. Operations owner. |
| BrainX self-grades or acquires final decision authority | `independent_critique` excludes the generation registration/provider/model; `brainx:execute` is DB-constrained from final scopes; service admin is denied | Provider/model independence is a minimum control; evaluation-quality governance remains a human/model-risk responsibility. Model-governance owner. |
| Secret or sensitive evidence leaks through API logs, errors, telemetry, graph/vector projections, or browser data | Structured redaction at the operational telemetry boundary removes credentials, database URLs, provider-key patterns, and configured protected fields; tenant/correlation values are hashed | Existing historical logs/projections require retention/deletion propagation before production. Security operations owner. |
| Production starts with an insecure authority, authentication fallback, missing encryption/secrets, or unrestricted egress | Startup fails closed for file authority, non-durable workflow, dev auth, and missing secure operational configuration | Deployment must provide real secrets provider, encryption reference, allowlist, staging/production identities, and egress enforcement. Platform owner. |
